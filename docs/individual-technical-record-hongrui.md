**Role and contribution.** My main role is User Interface and Input. The team roster still lists my formal sub-role as TBD. I implemented the shared input actions and pause/settings UI, the title/day-select/stage-clear/game-over flow, a HUD for time/lives/score/day progress, the bike transition, and four microgames: Canvas upload, Schedule Builder, Stay Focused, and Logic Gates. The main programming contribution is a playable five-day loop that loads a microgame, receives its result, updates lives or score, and routes to the next screen.

**Where to find it.** [PR #3](https://github.com/Luna020204/AggieWare/pull/3) contains the work. The flow is in `scripts/core/game_flow.gd` and `scenes/core/game_flow.tscn`; the HUD is in `scripts/ui/game_hud.gd`; shared controls and pause state are in `scripts/core/input_actions.gd`, `scripts/core/game_state.gd`, and `scripts/ui/settings_pause_menu.gd`. Each microgame has a script and scene under `scripts/microgames/` and `scenes/microgames/`. `tools/smoke_flow.gd` is the flow check. Key commits: `fa52351` (shared input and initial scenes), `4c73bdd` (connected loop and HUD), and `4730fe8` (three more microgames).

**How it works.** `GameFlow` owns the current day, lives, score, and screen state. On a day start it instantiates the mapped microgame and HUD. All microgames emit `time_changed(seconds_left, round_seconds)` for the HUD and `round_completed(success)` for the flow. Success adds 100 points and shows stage clear. Failure costs one life; the bike transition retries the day while lives remain, and the game-over screen appears at zero lives. Stage clear advances through the bike transition. I kept the microgames independent scenes with the same two-signal contract so each can be tested alone with F6 and substituted without changing the HUD or menu code. Controls are read through the shared `InputActions` autoload; `GameState` owns pause state.

**Team connection.** The root Godot scene and `GameFlow` provide the handoff point for the core loop and other teammates' future microgames. `stage_selected` and `microgame_requested` signals expose day changes to other systems. The current repository contains no verified teammate-authored stage manager integration, so the signal contract and day-to-scene mapping should be checked together during the next integration pass.

**What changed during testing.** The first flow screen displayed a placeholder instead of loading a microgame; I connected Canvas, the bike transition, and HUD, then added the remaining scenes. A dynamic UI cleanup bug caused Godot to reject synchronous deletion during a button signal, so the flow now uses `queue_free()`. I also fixed mouse release outside a dragged Canvas card and corrected low-contrast file labels after inspecting rendered scenes. Godot 4.7.2 editor import passes; `godot --headless --path . --script res://tools/smoke_flow.gd` prints `FLOW_SMOKE_OK` after success, stage transition, schedule registration, shield collision, gate placement, three lost lives, retry, and end-of-week checks.
